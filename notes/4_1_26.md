## Morphological Processing

- Collection of non-linear operations that relate to the shape and geometric structure of features within a merge
- Usually have [IMG] -> [model] -> [binary output] (is noisy)
- Rather than operating on pixel brightness or intensity, this works directly on he structural composition of objects (in ex. just working on binary image, 1/0)
- GOALS:
    - Clean noise
    - Smooth boundaries of objects
    - Seperate artifically connected objects
    - Fill gaps & holes 
    - Define outer envelope of features you want to find / geometric structures

## Example
- Let A = {(x,y) | A(x,y) = 1} => image
- Let B = {(u,v)} => structuring element

- **EROSION**
    - A (-) B = {z | Bz intersection A}
    - Logical AND operation
    - Every pixel must be 1 (within the structuring element) to stay as 1
- EFFECTS:
    - Boundaries more inward
    - Small isolated noise is removed
    - Some features will be full eliminated


- **DIALATION**
    - A (+) B = {z | Bz U A}
    - Logical OR operation
    - Any pixel must be 1 to stay as 1
- EFFECTS:
    - Boundaries moved outward
    - Small holes get filled
    - Nearby objects merge together

- These operations in isolation might not be particularly useful, only when you chain them together do you see the real useful results
## Chained operations
- OPENING: A o B = (A (-) B) (+) B
    - Fill holes
    - Create more continuous features
    - Smooths boundaries
    - Doesn't affect the overall area
    - First constructing the boundary, then expanding it (first like noise removal, then amplifying things that remain from output of erosion)
    - Preserves area that you originally have while removing any of the spurious detections

- CLOSING: A * B = (A (+) B) (-) B
    - Also fills holes
    - Creates more continuous features
    - Smooths boundaries
    - Defines an envelope

- Closing closes holes in data, opening gets rid of salt & paper noise
    - Almost never do a dialation or erosion itself

## Spatial Filtering
- Value of a target pixel is altered based on the values of the pixels in its immediate geometric neighborhood
- Just like morphological but also using intensity values
    - Morph might be useful on the classification stage
    - This stuff might be useful at the input stages and in downstream stages too
- Using **convolutions**
- Scenario
    - Imagery is inherently noisy
    - Atmosphere, sun flint, complex grand features
    - Want to sharpen image to specific frequencies
    - Remove localized anomalies

- **Gaussian filter**
    - G(x,y) = 1 / (2*pi*sig^2) e ^ -(x^2 + y^2) / (2*sig^2)
    - Linear low pass filter (removes high frequency noise)
    - Blurs fine details, surpresses outliers
    - Can introduce values that have never existed from sensors

- **Median filter**
    - Take median of values in kernel
    - This is a non-linear filter (median is not a linear operation)
    - Picks from values within window/neighborhood so it's constrained to current values
    - Preserves edges & surpresses noise

- **Bilateral filter**
    - Non-linear edge preserving smoothing filter
    - Attempts to take the best out of both what gaussian and median filters do
    - Replace pixel values with a weighted average of enarby pixels (kinda sounds like gaussian) but we use two distinct gaussians now
        1. Spatial kernel = Spatial distance (proximity) just like before
        2. Range kernel = Intensity filter again just like before - pixels with intensity values similar to the center pixel are weighted higher

## Edge detection
- Use second derivative to find edges
- Lapalce stuff too

- Canny edge detector
    1. Low error rate
    2. Good localization
    3. Minima response to noise
    - Steps:
        A. Smooth with gaussian
        B. Gind gradients w/ sobel
        C. Perform Non-Maximum Surpression => thin edges
            - Thins edges by surpressing non-max gradients values
            - Only local maxima in direction of gradient retained
        D. Double threshold
            - Bucket things into strong, weak, and non-relevant
        E. Hystoresis => edge tracking
            - Looking at connectivity between strongly classfieid gradient values and weakly classified gradient values (connect segments and do test)
            - Preserve strong connections
            - Weak -> strong = keep
            - Everything else you discard

## Color spaces
- RGB: Red, green blue
    - Additive color model
    - (0, 0, 0) => black
    - (255, 255, 255) => white
- CMYK: Cyan, magenta, yellow, key (black)
    - Subtractive color model
    - More ink = darker
    - Color gamut (possibilities) is smaller than you can achieve compared to RGB
- HSV: Hue, saturation, value
    - This is how we, with our eyes, percieve color
    - This is how we normally see color
    - On a scale of like degrees with red being 0 degrees, green being 120 degrees, blue at 240 degrees, and back to red at 360 degrees
    - It's easy to translate between HSV and RGB space
